# PROMPT #246 - Deep Pipeline: Project Enrichment & Card Status

## Objective

Fix the deep pipeline to properly populate project fields (description, context_semantic) and mark generated cards as DONE after completion. Previously, the pipeline generated cards, wiki, and a quality score but left the project's description and context fields empty, and all cards were created as BACKLOG even though they represent already-implemented code.

## What Was Implemented

### 1. Project Enrichment (Description + Context Semantic Generation)

Added a post-Phase 7 enrichment step that uses AI to generate:
- **Project description**: Human-readable summary of what the project does (200-2000 chars)
- **Context semantic**: AI-optimized technical context for future AI interactions (300-5000 chars)

This follows REGRA #0 — only fills empty fields, never overwrites human-edited data.

### 2. Cards Marked as DONE

All cards (Epics, Stories, Tasks) generated by the deep pipeline are now marked as `DONE` instead of `BACKLOG`, since the pipeline analyzes EXISTING code — the features described in cards are already implemented.

### 3. Contract YAML for Enrichment

Created externalized prompt following project conventions (YAML in contracts folder, not hardcoded).

## Root Cause Analysis

The deep pipeline was designed with 7 phases focused on:
- Phase 0: Structural scan
- Phase 1-2: File analysis and rule synthesis
- Phase 3: Architectural map
- Phase 4: Card generation (Epic/Story/Task)
- Phase 5: Wiki generation
- Phase 6: Quality assurance
- Phase 7: Gap filling

**None of these phases wrote to project.description or project.context_semantic.** These fields were only populated by:
- `rag_pipeline.py` (for description)
- `context_interview.py` (for context_semantic)

The deep pipeline is a separate code path that had no integration with project enrichment.

**Card status** was always set to `BACKLOG` because the card generation phase didn't consider that the deep pipeline scans existing code (not planned features).

## Architecture Decision

The enrichment step was placed AFTER all 7 phases complete (not as a new phase) because:
1. It uses artifacts from multiple phases (arch_map, domain_rules, card_stats, wiki_stats)
2. It's a lightweight post-processing step, not a core analysis phase
3. It's non-fatal — if it fails, the pipeline still completed successfully
