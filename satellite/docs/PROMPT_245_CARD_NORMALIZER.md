# PROMPT #245 - Card Format Normalizer
## Standardize from_rag Cards to ORBIT Format Specification

**Date:** February 21, 2026
**Status:** COMPLETED
**Priority:** HIGH
**Type:** Feature Implementation
**Impact:** All 499 from_rag cards normalized to match ORBIT's proper format; normalization now runs automatically after every card creation

---

## Objective

Cards generated by the RAG pipeline were poorly formatted:
- Titles were raw domain names or rule text (not Portuguese, not user-story format)
- Descriptions had minimal structure (just `# Title\nDomain: X`)
- Generated prompts lacked proper semantic map structure
- Acceptance criteria used "Implement:" / "Validate:" prefixes instead of "ACn:"
- Story points were wrong (Stories had 8 instead of 5)

**Solution:** Create a normalization script that reformats all cards to match ORBIT's specification, then integrate it as an automatic post-processing step.

---

## What Was Implemented

### 1. Card Normalizer Script (`backend/scripts/normalize_cards.py`)

Standalone script and importable module that normalizes from_rag cards:

**Title normalization:**
- Epics: Portuguese business-focused titles (e.g., "Orquestracao de IA e Multi-Provider")
- Stories: User story format ("Como [user], eu quero [action]")
- Tasks: Functional+technical, max 80 chars
- Subtasks: Action-specific, max 100 chars

**Description normalization:**
- All types: Proper markdown with ## Contexto, ## Regras de Negocio, ## Nivel sections
- Epics: Include stories list and full rules
- Stories: Business rule contextual descriptions
- Tasks: Balanced functional+technical
- Subtasks: Objectively technical with implementation instructions

**Generated prompt normalization:**
- Epics: `# EPIC: [Title]` + `## Mapa Semantico` + `## Regras de Negocio` + `## Instrucoes`
- Stories: Inherited identifiers from parent epic
- Tasks: Technical identifiers (files, methods)
- Subtasks: Code-level specification

**Acceptance criteria normalization:**
- Format: `"ACn: [criterion]"` (max 6 per card, each max 200 chars)
- Fallback templates per item_type

**Story points correction:**
- Epic: 13, Story: 5, Task: 3, Subtask: 1

**REGRA #0 compliance:**
- WHERE clause: `description_edited_by != 'human' AND prompt_edited_by != 'human'`

### 2. Pipeline Integration

Normalization runs automatically in 3 locations:
1. **`claude_full_pipeline.py`** - Phase 4 after card creation
2. **`business_rules.py`** - After both hierarchical and flat card creation
3. **`pipeline_cards.py`** - After incremental batch card creation
