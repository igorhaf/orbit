# Validação de acessibilidade do Suindá

Esta validação complementa as verificações de acessibilidade já executadas no Orbit/Suindá. Os roteiros acessam somente o ambiente indicado, não alteram registros e não enviam dados a provedores externos.

## Pré-requisitos

- Web e API da prévia em execução; por padrão, Web em `http://localhost:3003`.
- Chrome/Chromium e dependências instaladas no workspace.
- Para examinar rotas autenticadas, configure `SUINDA_A11Y_EMAIL` e `SUINDA_A11Y_PASSWORD` de uma conta de auditoria com dados representativos. Os scripts nunca imprimem esses valores. Não use credenciais de uma pessoa real.
- Para outro endereço, defina `SUINDA_A11Y_BASE_URL`, por exemplo `SUINDA_A11Y_BASE_URL=http://localhost:3003`.

Ela usa identidade e respostas de API simuladas pelo runner, então complementa a inspeção anônima sem substituir dados reais, leitores de tela ou estados de interação não abertos.

Os roteiros de axe, teclado e contraste são instrumentos de triagem automatizada. Nenhum resultado substitui avaliação com leitores de tela, ampliação real, navegação manual por fluxos completos, inspeção de conteúdo autenticado representativo ou revisão humana de legenda e transcrição. Resultados sintéticos e anônimos são registrados como tais.

O roteiro autenticado usa token inválido fora do navegador e intercepta toda chamada `/api/` antes da rede; rotas externas são bloqueadas. A identidade ROOT e os payloads mínimos são fixtures para renderizar componentes que dependem de estado autenticado. Uma aprovação demonstra apenas que essas páginas e estados sintéticos passaram os critérios automatizados implementados pelo roteiro. Não demonstra validação de sessão/permissões, conteúdo populado, uso de APIs reais nem conclusão de jornada funcional. `SUINDA_AUTH_A11Y_ROUTES` permite executar um subconjunto de caminhos para diagnóstico, sem remover as rotas da cobertura padrão.

ESLint, TypeScript e build Web passaram nos dois worktrees: 22 páginas no Orbit DEV e 40 no Suindá. Não houve interação por navegador nesta etapa; compilação e integração de componentes não comprovam o comportamento real de foco nem leitura por tecnologia assistiva. A mudança foi aplicada no Orbit DEV e no Suindá; o build verifica integração, mas o conteúdo do diálogo ainda requer teste interativo antes de ser incluído como evidência funcional.

O painel Alexa Orbit também substituiu seu manejo manual de foco por esse modal nos dois worktrees. Assim o fechamento por Escape, a contenção completa do foco e sua restauração seguem o mesmo contrato compartilhado; o painel recebe a classe de tema claro/escuro da instalação.
